# 編集・運用ガイド

## サイトの構成

Astroの1ページ構成です。入口は`src/pages/index.astro`、全体のHTMLは`src/layouts/Layout.astro`、共通スタイルは`src/styles/global.css`です。

ページの順番：ヒーロー → お困りごと・費用案内 → 品目・サービス → ご相談の流れ → 実績 → エリア → FAQ → 電話相談 → 会社情報。

## ご相談の流れのアニメーション

「HOW IT WORKS」は、PCで横方向、幅800px以下で縦方向につながる4ステップです。各段階に電話・内容確認・日程調整・対応のアイコンを置き、画面に入ったステップから順番に円と接続線に色を入れます。自動演出は表示時の1回のみで、常時ループしません。

「流れをもう一度見る」ボタンで、画面内にあるステップの演出を再生できます。スマホではスクロールして次の段階が見えると、その段階の演出が始まります。説明文は最初から表示され、アニメーションによって読めなくなることはありません。実際の依頼の進行状況を表示する機能ではなく、ご相談の手順を説明する演出です。

動きを減らす端末設定ではアニメーションを使わず、色の付いた完成状態で表示します。JavaScriptやIntersectionObserverが使えない場合も、アイコン・接続線・説明を表示します。

## サイト全体のGSAPアニメーション

`src/layouts/Layout.astro`から`src/scripts/motion.ts`を読み込んでいます。導入済みのGSAPを使用し、表示の判定はブラウザーのIntersectionObserverで行います。ScrollTriggerによる発火位置の保存・再計算は廃止しました。依存関係の追加は行っていません。

| 対象 | 演出 |
| --- | --- |
| ヒーロー | 最初から通常表示。画面幅の変更で見出しを再演出しない |
| セクション見出し・お困りごと | 初期表示で画面外にあるものだけ、少し下からフェードイン |
| 品目画像 | 項目全体が一度だけフェードイン。画像を切り抜く演出は廃止 |
| OUR SERVICES・営業実績 | 各項目が画面に入ると一度だけ表示。実績の数字自体は変更しない |
| エリア・会社情報 | 説明ブロック単位でフェードイン。会社情報の表はまとめて扱う |
| FAQ | 見出しのみスクロール表示。開閉は専用の`faq.ts`で回答領域の高さをアニメーション |
| お問い合わせ | 見出し・文章が一度だけフェードイン。装飾のスクロール連動移動は廃止 |

表示演出は各要素につき1回です。初期設定時の移動距離はPCで16px、スマートフォンで10px、再生時間は0.65秒です。同時に画面へ入った要素の時間差は最大0.18秒に抑えています。「HOW IT WORKS」のアイコンと線の演出は引き続き`flow.ts`で管理し、二重にアニメーションを掛けません。

本文は初期HTMLから表示します。初期化時点ですでに見えている要素と、画面より上にある要素には演出を設定しません。画面下にある対象だけを見えない状態で準備し、画面内へ入るとGSAPの`to()`で通常表示へ戻します。表示後に`fromTo()`で透明度を落とし直す処理は廃止しました。JavaScript実行前にCSSで本文を隠す処理はありません。

再生を始める直前に、その要素の監視を解除します。画面幅や高さが変わっても全要素を初期化し直さず、表示済みの要素は再生しません。FAQを開いてページの高さが変わっても、監視対象はブラウザーが現在のレイアウトで判定するため、手動で発火位置を再計算しません。電話ボタンの待機や、ヒーロー画像の拡大・移動は行いません。

端末の「動きを減らす」設定ではGSAPの演出を停止し、準備中を含む全要素を通常表示へ戻します。その後に設定を戻しても、表示済みの内容を再び隠しません。リンク等にキーボードフォーカスが入ったときは、その要素を含む表示演出を即座に完了させます。GSAPのスタイルは1つのcontextで管理して解除し、二重の復元処理を避けています。スクロールは後述のLenisで補間します。スクロールに連動したセクション固定・自動の強制移動・無限ループは設けていません。

参照：[GSAP context](https://gsap.com/docs/v3/GSAP/gsap.context()/)、[Astroのスクリプト処理](https://docs.astro.build/en/guides/client-side-scripts/)。

今回もユーザーの指定により、実装後のビルド・型チェック・テスト・ブラウザー確認は行っていません。

## Lenisと追従ヘッダー

導入済みのLenis 1.3.27を`src/scripts/scroll.ts`で適用しています。このモジュールは`navigation.ts`から読み込み、インスタンスを1つだけ生成します。標準CSSも`Layout.astro`で読み込みます。

- ホイール操作を`lerp: 0.12`で補間します。タッチ操作は`syncTouch: false`とし、端末標準の操作感を保ちます。
- `autoRaf: true`で1本のフレームループを使います。GSAP tickerへの登録や独自のRAFループは追加していません。
- ページ内リンクはクリックを受けてLenisの`scrollTo()`で移動します。修飾キー、新しいタブ、外部リンク、電話リンクには介入しません。
- ページ内リンクの移動後は対象へフォーカスを移し、URLのハッシュと履歴も更新します。スキップリンクは即座に移動します。
- 固定ヘッダー分の余白は、ルートの`scroll-padding-top: calc(var(--header-height) + 20px)`で統一します。Lenis 1.3.27はこの値を読むため、JavaScriptで同じ余白を重ねて加算しません。
- CSSの`scroll-behavior`は`auto`とし、Lenisとの二重のスムーズスクロールを避けます。
- モバイルメニューを開いている間はLenisを停止し、ページ背景をロックします。メニュー内は`data-lenis-prevent`で通常どおりスクロールできるようにします。
- メニュー内リンクを選んだ場合は、閉じる処理とロック解除を先に行ってからページ内を移動します。
- 動きを減らす設定ではLenisを破棄し、通常のスクロール・ページ内移動を使います。
- FAQの開閉等による文書サイズの変更は、Lenisの`autoResize`に任せます。

ヘッダーは`position: fixed`で常に画面上部に表示します。高さは既存のレスポンシブ変数に合わせ、スクロール中も縮めません。背景色を付け、16px以上スクロールしたときに境界線と薄い影を表示します。ヘッダーの位置や移動先の余白は`global.css`、スクロール状態とメニューは`navigation.ts`で管理します。

参照：[Lenis公式ドキュメント](https://github.com/darkroomengineering/lenis#readme)。本プロジェクト内の1.3.27の型定義・実装も参照して設定しました。

## Q&Aの開閉

`src/components/Faq.astro`から`src/scripts/faq.ts`を読み込みます。GSAPで回答パネルの高さだけを動かし、文字の透明度や位置は変更しません。開く時間は0.36秒、閉じる時間は0.28秒です。

閉じる途中も`details`の`open`を維持し、高さが0になってから閉じることで回答が瞬間的に消えるのを避けています。連続クリック時は進行中の動きを止め、その瞬間の高さから反対方向へ動かします。開き終わると高さの固定を解除し、端末サイズや文量の変化に追従します。開いている途中に折り返しが変わった場合も、回答の自然な高さを再取得します。

質問は標準の`summary`を使い、Enter・Spaceによる操作を維持します。開閉状態は`aria-expanded`へ反映し、閉じる途中の回答は`inert`で操作対象から外します。閉じ終わった後の非表示は標準の`details`に任せ、ブラウザーのページ内検索による展開も受け付けます。動きを減らす設定では即座に開閉します。JavaScriptが実行されない場合は、標準の`details`として開閉できます。

スクロール用のGSAP処理は回答パネルを操作しないため、開閉と二重に透明度や高さを変更しません。

## サービス・品目の追加

サービスは`services.ts`の配列に追加できます。遺品整理の作業内容や対応範囲が確定したら、該当サービスと`faqs.ts`の回答を一緒に更新してください。

品目は`items.ts`に追加します。対応範囲を確認できていない品目は`publish: false`にすることで一覧に出さず保持できます。画像を追加するときはimportとデータの`image`を指定します。

品目の掲載は、無条件の回収・買取を保証するものではありません。品目欄の料金・対応条件の文面もあわせて管理してください。

## 許可情報・LINE

- 古物商許可情報は正式な許可証と照合したあと、`site.ts`の`permit`を`{ authority: '正式な公安委員会名', number: '正式な許可番号' }`へ変更します。会社情報欄に表示されます。
- LINEは確認済みの友だち追加URLを`lineUrl`に設定すると、お問い合わせ欄にリンクが表示されます。連絡先の数字からURLを作らないでください。
- 定休日・保有資格・来店受付・支払方法などは未提供です。確認した内容だけを追加します。

## 文字・フォント

日本語は端末内のゴシック体（ヒラギノ、游ゴシック、メイリオ等）を使用します。Google FontsのNoto Sans JPと、関連する外部CSS・事前接続の読み込みは削除しました。`display=swap`によってページ表示後に書体・文字幅・改行が切り替わる要因を除いています。

フォント指定は`src/styles/global.css`の`:root`にあります。電話番号等の数字は引き続きArial等を使います。具体的な書体は端末の搭載フォントにより異なりますが、ページの表示後にWebフォントをダウンロードして差し替える構成ではありません。フォントを待つために本文を隠す処理や、ローディング画面は設けていません。

## 画像

### ヒーローの画面サイズ対応

ヒーローは固定pxの高さを使わず、`100dvh`を基本に画面の表示領域へ合わせています。ヘッダーは画面上部に固定してヒーローに重ね、ヘッダー分の高さが別途加算されない構成です。スマートフォンでは下部の固定電話ボタンとセーフエリアに必要な余白を確保します。

デスクトップ（幅801px以上）の画像は`object-fit: cover`と`inset: 0`でヒーロー全体を覆います。画像用に下部の空白を確保せず、ヘッダー・キャッチ・出張案内は背景画像に重ねます。画面との縦横比の差は中央を基準にトリミングし、上下左右に空白が出ない表示です。下部には薄い生成りのグラデーションを重ね、出張案内の読みやすさを確保しています。

幅800px以下は引き続き`object-fit: contain`で画像全体を表示し、固定電話ボタンと案内のスペースを確保します。画面の縦横比が4:5以下の場合は縦構図、それ以外は横構図の画像を選びます。

ヒーロー専用の電話ボタンは`Hero.astro`にあり、ページ下部の電話ボタンとは別に見た目を調整できます。短い画面や横向き画面にも専用のCSSを用意しています。

- 使用画像：`src/assets/generated/`。
- 生成原本：`src/assets/generated/originals/`。
- SNS共有画像：`public/ogp.jpg`（1200×630）。
- ファビコン：`public/favicon.png`。
- 端末用アイコン：`public/apple-touch-icon.png`、`public/icon-192.png`、`public/icon-512.png`。
- 生成時の指示全文と原本の取り込み先：`scripts/generated-assets.json`。

原本からWeb用画像を作り直す場合は`node scripts/prepare-assets.mjs`を使用できます。既にプロジェクト内に原本があれば、その原本を使います。この処理はAI画像の再生成を行いません。

古いAstro初期アイコンの`public/favicon.svg`・`public/favicon.ico`はHTMLから参照していません。

## 開発サーバー

AGENTS.mdに従ってバックグラウンド起動します。

```powershell
npm run astro -- dev --background
npm run astro -- dev status
npm run astro -- dev logs
npm run astro -- dev stop
```

上記は`astro dev --background`等をローカル依存関係から実行する方法です。サーバーのURL・ポートは起動時の表示を参照してください。

この作業環境では、既定の`node`コマンドが指定バージョンを見つけられなかったため、画像の形式変換にCodex同梱のNode.jsを使用しました。`package.json`の既存のNode指定や依存関係は変更していません。お使いのNode環境が既存の指定バージョンを利用できる状態で、開発コマンドを実行してください。

## 公開URLの設定

本番URLは`https://midori-recycle.pages.dev/`です。`src/config/seo.mjs`で管理し、Astroの`site`、canonical、OGP、構造化データ、robots.txt、サイトマップから共通参照しています。ドメインを変更する場合はこの設定を更新してください。

`Seo.astro`はcanonical・og:url・OGP画像を絶対URLで出力します。タイトル・説明は`src/data/site.ts`、会社情報・サービスのJSON-LDは`site.ts`と`services.ts`の掲載データを参照します。

`src/pages/robots.txt.ts`と`src/pages/sitemap.xml.ts`で静的ファイルを生成します。現在のサイトマップ対象はトップページのみです。ソース変更後の再デプロイ・Search Consoleへの登録・インデックス確認は行っていません。設定と公開後の手順は`docs/SEO.md`を参照してください。
